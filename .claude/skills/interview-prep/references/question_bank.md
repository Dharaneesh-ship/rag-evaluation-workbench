# 面试题库 — 三方向完整题库（RAG Framework）

> 本文件供面试官（AI Agent）在面试时随机选题使用。
> SKILL.md 中指定的随机规则（基于 `[DICE]` 掷骰）从本文件各题池中抽取当场问题。
> **每次面试不得连续使用同一道题作为开场，严禁每场都从编号最小的题开始。**
> 所有题目均基于 `rag-framework` 项目真实实现（FAISS + BM25 + RRF、Cross-Encoder/Voyage Rerank、FastMCP、SQLite Trace/DocStore），不涉及原始参考项目（Chroma/MarkItDown/ChunkRefiner 等）里不存在的组件。

---

## 方向 1 题库：项目综述

### 【开场题池】（共 12 道）

选取规则：`[DICE] × 2 - 1` 对应的题（骰子 1→1, 2→3, 3→5, 4→7, 5→9, 6→11）

1. 介绍一下这个项目整体解决什么问题，架构分哪几层？
2. 从用户发起一次查询，到拿到结果，整个链路经过哪些组件？
3. 这个系统里 MCP 协议起什么作用？Server 用的是什么 Transport？
4. 如果让你给一个没接触过 RAG 的同学介绍这个项目，你会怎么说？
5. 这个项目里你认为最复杂的模块是哪个？为什么？
6. 和传统文档检索系统相比，这个系统的核心差异点是什么？
7. 这个系统里有哪几类存储？它们各自负责什么？为什么不能只用一个？
8. 如果重排（Rerank）服务挂了，系统会怎么表现？有降级机制吗？
9. 这个项目的测试覆盖率是怎么保证的？测试分几层？
10. 从工程化角度，这个项目里最体现软件设计原则的地方是哪里？
11. 如果要把这个系统部署给多个团队使用（多租户/多 collection），现有架构需要做什么改动？
12. 这套系统在什么情况下检索效果最差？你们做过什么来缓解这种情况？

### 【追问候选池】（共 10 道）

选取规则：仅作为即兴追问的灵感来源，不直接选取——追问必须基于候选人实际回答重新构造

1. Ingestion 链路具体经过哪些阶段？哪个阶段最耗时？
2. Hybrid Search 的两路是怎么融合的？为什么用 RRF 而不是直接加权平均？
3. MCP 用的是 stdio 还是 HTTP？docker-compose 里映射的端口是干嘛的？
4. 项目里的幂等性设计体现在哪里？具体怎么实现的？
5. 可插拔架构是怎么实现的？举一个你新增 Provider 的例子。
6. 系统里用了哪些存储？（FAISS / BM25 / SQLite DocStore / SQLite TraceStore）各自存什么？
7. 评估体系里 Recall@K 和 MRR 各衡量什么？你一般关注哪个更多？
8. Trace 是怎么工作的？Query 链路的几个阶段各记录了哪些数据？
9. 扫描版 PDF 是怎么处理的？和普通 PDF 走的是同一条解析路径吗？
10. 这个系统里有没有什么"过度设计"或明显的设计缺口？现在回头看你会怎么改？

## 方向 2 题库：简历深挖（包装识别）

### 【P1 — 量化指标追问池】（简历有数字时必进，共 6 道）

选取规则：由 `[DICE]` 直接选取（超出长度则循环）

1. 你提到检索准确率/Recall 提升了多少，这个是怎么测量的？测试集有多少条？是人工标注的还是自动生成的？
2. 你提到的延迟数字是在什么硬件环境下测的？并发量是多少？
3. 这个数字是在什么 baseline 下对比的？对比方案是什么？变量控制了吗？
4. 这个指标是在真实语料还是评估集上测的？两者一般会有多大差异？
5. 你提到的测试用例数（1100+），这些测试分几层？各测什么？
6. 如果我现在跑你们的评估脚本，能复现你简历上的数字吗？评估代码在哪？

### 【P2 — 强动词追问池】（简历有"主导/设计/独立完成"时，共 8 道）

选取规则：由 `[DICE]` 直接选取（超出长度则循环）

1. 你说你主导了 Ingestion Pipeline 的设计，当时有哪些方案备选，为什么选现在这个分阶段结构？
2. 你独立完成了 Hybrid Search，有没有遇到什么难点？是怎么解决的？
3. 你说你设计了文档生命周期管理，删除一个文档时 DocStore 和检索索引分别是怎么保持一致的？
4. 你说你实现了 FAISS + BM25 融合，RRF 里的 k 值是你调的吗？调整依据是什么？
5. 你说你设计了可插拔架构，那新增一个 Embedding Provider 具体需要改哪些文件？
6. 你说你做了评估体系，Resume Gold Eval 这 30 条标注数据是你标的吗？标注流程是什么？
7. 你说你实现了 MCP 集成，7 个工具的输入输出 Schema 是你设计的吗？
8. 你说你做了可观测性，Trace 数据是怎么存储的？为什么选 SQLite 不用 LangSmith 这类现成工具？

### 【P3 — 技术词汇追问池】（简历有技术关键词时，共 10 道）

选取规则：由 `[DICE]` 直接选取（超出长度则循环）

1. 你提到 RRF，k=60 这个参数是怎么来的？你有调过吗？调大调小各有什么效果？
2. 你说用了 Cross-Encoder 精排，具体用的是哪个模型？和 Voyage Rerank 相比你会怎么选？
3. chunk_id 是怎么生成的？为什么不用 UUID？如果文档只改了一段，chunk_id 会怎么变？
4. 删除一个文档时，索引层（FAISS/BM25）和 DocStore 层的删除机制一样吗？
5. 你提到扫描 PDF OCR，具体用的什么渲染 + 识别方案？
6. 你提到增量摄取，具体是怎么判断一个 chunk 是否需要重新处理的？
7. 你的测试里怎么 mock LLM 调用？mock 的是哪一层？
8. BM25 的 b 参数和 k1 参数你们有调过吗？
9. FAISS 用的是什么索引类型？相似度是怎么计算的？
10. RAGAS 的 Faithfulness 指标具体衡量什么？和 Recall@K 有什么本质区别？

### 【无简历题库】（无简历时随机选 2-3 道，共 8 道）

选取规则：由 `[DICE]` 直接选取（超出长度则循环）

1. 如果有人在简历上写"主导设计了 Hybrid Search 提升 Recall 30%"，你觉得面试时应该怎么验证他是否真正懂？
2. Ingestion Pipeline 里哪个阶段最容易出 bug？为什么？
3. 如果要给这个项目的某一个模块写简历项目经历，你会选哪个？会怎么写量化指标？
4. 这个系统里有什么设计你觉得可以改进的？如果你重新做会怎么架构？
5. 如果 Reranker 调用失败，系统会有什么表现？用户能感知到吗？
6. 你觉得这套系统最大的技术风险是什么？如何缓解？
7. 如果要给 MCP Server 换成 HTTP Transport，现有代码需要改哪里？
8. FAISS 用的是 IndexFlatL2，如果语料规模涨到百万级，你会怎么改？

## 方向 3 题库：技术深挖（共 55 道）

> **选取规则：**
> 1. 若有简历，根据简历关键词匹配对应主题组，汇总所有候选题
> 2. 无简历则使用全部 55 道题作为候选池
> 3. 按 `[DICE]` 选主题组（1→A, 2→B, 3→C, 4→D, 5→E, 6→F），再从该组中选第 `[DICE]` 道题
> 4. 严禁与同会话上场面试重复超过 1 题

### 【A — 检索架构】关键词：Hybrid Search / RRF / BM25 / FAISS / 混合检索

A1. RRF 公式是什么？k 值怎么选？为什么不用线性加权？
A2. BM25 相比 TF-IDF 改进了什么？项目里 b/k1 参数是怎么设置的？
A3. IDF 依赖的文档频率存在哪？重新摄取文档时 BM25 索引怎么更新？
A4. FAISS 用的是什么索引类型（Flat/IVF/HNSW）？相似度是余弦还是 L2？
A5. 如果用户查询全是专有名词，纯向量检索会有什么问题？项目怎么缓解的？
A6. Top-K 的 K 怎么定？召回太少和召回太多分别会有什么影响？
A7. Hybrid Search 里 Dense 和 Sparse 两路的召回数量一样吗？如果不一样，RRF 还有效吗？
A8. 如果两路检索结果完全不重叠，RRF 融合后会是什么结果？
A9. FAISS 检索有没有设相似度阈值？设阈值有什么风险？
A10. BM25 对中文分词有什么依赖？项目里怎么处理中文？

### 【B — 精排 Reranker】关键词：Rerank / Cross-Encoder / Voyage / 精排 / 二阶段检索

B1. Cross-Encoder 和 Bi-Encoder 的区别？为什么 Cross-Encoder 不能做粗排召回？
B2. 精排候选集多大合适？K 开太大会有什么问题？
B3. Cross-Encoder 和 Voyage Rerank 两种后端你会怎么选？分别的优劣是什么？
B4. 精排失败时系统怎么处理？有没有 Graceful Fallback？
B5. Cross-Encoder 推理时输入是什么格式？Query 和 Chunk 是怎么拼接的？
B6. 如果 Reranker 模型在语言上有偏差（比如英文模型处理中文），会有什么表现？
B7. 精排后有没有分数阈值过滤机制？
B8. 你们用的具体是哪个 Cross-Encoder 模型？选它的理由是什么？

### 【C — 数据摄取 Ingestion】关键词：Ingestion / Pipeline / Block Splitter / Chunk Packer / 摄取流水线

C1. Ingestion Pipeline 具体分哪些阶段？每个阶段做什么？
C2. Block Splitter 和 Chunk Packer 的分工是什么？为什么要分两步？
C3. 文件级去重和块级差量各自防的是什么场景？为什么要两套机制？
C4. chunk_signature 是怎么计算的？和对整个 chunk 内容做哈希有什么区别？
C5. 项目支持哪些文档格式的解析器？各自用什么库？
C6. 扫描版 PDF 走的是哪条路径？和结构化解析的 PDF 有什么不同？
C7. 如果源文件更新了，怎么做增量更新？直接重跑现有逻辑会有什么问题？
C8. Quality Gate 阶段是做什么用的？摄取质量不达标会怎样？
C9. 如果 Embedder 调用失败（比如 API 超时），整个摄取任务会怎么处理？
C10. 项目里有没有用 LLM 做 chunk 内容优化或元数据生成？

### 【D — 架构 & MCP 协议】关键词：可插拔 / 工厂模式 / FastMCP / 插件架构

D1. 可插拔架构怎么实现的？新增一个 Embedding Provider 需要改哪些文件？
D2. 为什么用 "module.path:ClassName" 字符串注册，而不是直接注册类对象？
D3. MCP Server 用的是什么框架？默认 Transport 是什么？
D4. docker-compose 里给 MCP 服务映射了 8000 端口，这个端口实际有在监听吗？
D5. 注册新 Reranker 的映射关系存在哪里？是硬编码还是动态注册？
D6. `list_collections` 和 `retrieve_with_metadata` 这两个 MCP 工具各自什么场景下被调用？
D7. 如果 MCP Client 传来一个不存在的 collection 名，系统怎么处理？
D8. Base 抽象类里定义了哪些必须实现的接口方法？
D9. 配置文件 `settings.yaml` 是每次都重新读盘还是缓存的？
D10. 如果要把这个 MCP Server 改成支持远程访问（HTTP/SSE），大概需要改动哪里？

### 【E — 存储 & 幂等性】关键词：FAISS / BM25 / DocStore / chunk_id / 幂等 / SQLite

E1. chunk_id 是怎么生成的？为什么不用 UUID？如果文件改了一行，受影响的 chunk_id 会变吗？
E2. 删除文档时，DocStore 层和索引层（FAISS/BM25）各自是怎么删的？是同一套机制吗？
E3. BM25 索引存在哪里？当前的存储方式（pickle）有什么局限？
E4. DocStore 的表结构是怎么设计的？外键级联删除具体是怎么起作用的？
E5. collection 是怎么实现隔离的？是每个 collection 单独建索引，还是共用索引加过滤？
E6. 如果两个文件内容完全一样（只是文件名不同），doc_id 会相同吗？
E7. FAISS 索引是怎么持久化和重新加载的？涉及哪几个文件？
E8. 如果索引层删除操作执行到一半失败了，会导致什么后果？

### 【F — 测试 & 可观测性】关键词：pytest / mock / 评估 / Dashboard / Trace / RAGAS / BEIR

F1. 测试分几层？unit/integration/e2e 各测什么？用什么 pytest marker 区分？
F2. 单元测试怎么 mock LLM 调用？不 mock 的话有什么问题？
F3. Recall@K 和 MRR 怎么计算？分别能反映检索系统的什么能力？
F4. RAGAS Faithfulness 和 Answer Relevancy 分别衡量什么？
F5. Trace 是怎么实现的？Query 链路的几个阶段各记录了什么？
F6. Dashboard 里的 Query Traces 页面能看到什么信息？
F7. Resume Gold Eval 这个基准是怎么建立的？有多少条？和 BEIR SciFact 有什么区别？
F8. 为什么要同时接入 BEIR SciFact 这种公开基准和自己标注的评估集？
F9. Context Precision 指标和 Recall@K 的区别是什么？
F10. 如果一次策略变更（比如换了 Reranker 模型）导致评估分数下降，你们的处理流程是什么？

### 【G — 系统设计 & 扩展性（通用题，无简历时重点使用）】

G1. 从系统设计角度，RAG 和 Fine-tuning 的核心权衡是什么？
G2. 这个系统的性能瓶颈在哪里？FAISS 用 IndexFlatL2 意味着什么？
G3. 如果要支持实时增量摄取（文档修改后立即生效），现有架构需要改什么？
G4. FAISS IndexFlatL2 和 IVF/HNSW 这类近似索引相比有什么区别？你会在什么规模下考虑切换？
G5. 如果用户的查询是一段很长的文字，Embedding 模型会怎么处理？有没有截断风险？
G6. 这套系统目前不支持什么功能？如果要支持「对话式多轮 RAG」，需要改哪些地方？
G7. 如果要把 BM25 换成 Elasticsearch 做稀疏检索，可插拔架构是否覆盖了这个场景？改动量有多大？
